# Where the CrateDB JDBC driver answers differently from stock pgJDBC.
#
# DifferentialIT points both drivers at the same CrateDB, asks each of them
# every method of every JDBC interface an application reaches, and compares the
# answers. This file is the expected result of that comparison, and the only
# place the delta is written down as something a machine can check.
#
#   <kind> {disposition} [scope] <call> :: <why>
#
# The kind says what the machine saw:
#
#   differs    the two drivers answer differently, on purpose
#   unstable   the answer changes from one sweep to the next, so there is
#              nothing to compare — a session id, a backend pid, a clock
#   unchecked  the call raises something other than a SQLException
#   permissive the call answers on a closed object where JDBC has one refuse
#   malformed  the SQLState is not one, or not the one its class implies
#   inconsistent  the driver reports a setting it did not apply, having
#              inherited the behavior from pgJDBC (SelfConsistencyIT)
#
# The disposition says what is to be done about it, and is what separates a
# difference this driver chose from a fault it inherited and has not reported:
#
#   by-design    this driver's own choice; there is nothing to report
#   for-crate    an accommodation of something CrateDB does
#   spec         a reading JDBC leaves open, where neither driver is wrong
#   inherent     a property of what is being measured rather than a decision,
#                which is what a value differing per connection is
#   wont-file    a fault of pgJDBC's, recorded rather than reported
#   jdk          a default method java.sql supplies to every driver that does
#                not override it, so the behavior is the platform's and there is
#                nobody to report it to
#   pgjdbc-todo  a fault of pgJDBC's that should be reported and has not been
#   crate-todo   a fault of CrateDB's that should be reported and has not been
#   pgjdbc#3141  reported, and where the conversation is; likewise crate#123
#
# `grep -- '-todo'` is therefore the queue of what upstream has not been told,
# and an entry carrying a ticket that goes stale is upstream shipping the fix.
#
# A scope in square brackets holds an entry to the runs it belongs to: a
# connection property the suite is running under, `[!property]` for its absence,
# or `[>=6.4]` for the CrateDB releases that have the behavior. An entry may
# carry both a disposition and a scope, in either order.
#
# A call is named as the sweep names it, with the state the object was in
# appended where the sweep put it in one — ResultSet.getString(int)@closed. An
# entry naming no state covers that call in every state it answers the same way
# in, so a fact about what the driver is rather than what it is doing is said
# once. A state that changes either driver's answer needs an entry of its own.
#
# A call that answers differently and is not listed here fails the build, and
# so does a listed call that stopped doing what it says. Adding an entry is a
# decision that the difference is meant; it is not a way to quiet the sweep.

# The simple protocol. A statement sent this way is never parsed on its own,
# so nothing describes it and there is nothing for pgJDBC to answer a
# description from — it reaches for what a describe would have left and fails
# an assertion instead of saying it has none. Both drivers are affected.
#
# The assertion is what the sweep sees, because the suite runs with them on.
# It is not what an application sees: with assertions off the same request
# falls through into the simple-query path and the statement is executed, so a
# metadata call on an unexecuted INSERT performs the insert and answers null.
# The kind below records the throw; the worse half of this is the write.

unchecked {pgjdbc-todo} [preferQueryMode=simple] PreparedStatement.getMetaData() :: pgJDBC reaches for a description the simple protocol never asked for and fails an assertion, and with assertions off executes the statement instead.
unchecked {pgjdbc-todo} [preferQueryMode=simple] CallableStatement.getMetaData() :: pgJDBC reaches for a description the simple protocol never asked for and fails an assertion, and with assertions off executes the statement instead.
unchecked {pgjdbc-todo} [preferQueryMode=simple] PreparedStatement.getParameterMetaData() :: pgJDBC reaches for a description the simple protocol never asked for and fails an assertion, and with assertions off executes the statement instead.
unchecked {pgjdbc-todo} [preferQueryMode=simple] CallableStatement.getParameterMetaData() :: pgJDBC reaches for a description the simple protocol never asked for and fails an assertion, and with assertions off executes the statement instead.
